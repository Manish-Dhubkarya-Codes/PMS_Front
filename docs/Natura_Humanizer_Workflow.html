Natura Humanizer

Whole workflow in one document — NLP models, filters, AI detection, plagiarism / originality. Reference product: stealthwriter.ai. No internal spec files were attached; this is the source of truth.

1. What this product does

Natura takes AI-written or mixed documents and does three jobs that StealthWriter sells as one product: rewrite the prose so it reads like a person wrote it, score leftover AI patterns at document and sentence level, and check that the new wording is original.

These are two separate engines. Do not merge them into one slider.

  • AI removal — destroy LLM fingerprints (even rhythm, template transitions, hedge stacks, uniform fluency).
  • Plagiarism-free — the new wording must not match the input, your corpus, or the public web.
A synonym swap can look original and still scream AI. A humanizer can sound natural and still be 80% the same 3-grams as a Wikipedia paragraph. Both gates are required. No honest tool can promise 100% undetectable on Turnitin or GPTZero forever. Show scores. Never guarantee a vendor result.

2. Whole workflow

Every document follows the same path. Cheap jobs (Mini + V1) stay in Node and finish under 1.5 seconds per 1,000 words. Expensive jobs (Pro + V2 + web plagiarism) go through Redis / BullMQ.

document  (txt / md / html / docx / pdf-text)
    |
    v
PRE-FILTERS P0–P8     encode, strip hidden chars, language,
                      moderate, protect quotes / citations /
                      numbers / URLs / glossary  →  sentinels
    |
    +------------->   DETECT V1 / V2     Deep Scan BEFORE
    |
    v
HUMANIZE              Mini or Pro  ×  intensity 1–10
                      mid-filters M1–M8 live inside the rewrite
    |
    v
POST-FILTERS X1–X5    restore spans, clean punct,
                      meaning cosine, entity / number lock, grammar
    |
    +------------->   DETECT again       X6 gate
    |                 if AI-prob did not drop ≥ 0.08
    |                 rewrite ONLY flagged sentences   (max 3 passes)
    |
    +------------->   ORIGINALITY A B C D     X7 gate
    |                 rewrite only matching sentences
    |
    v
REPORT
    % Human before / after
    sentence colors + reasons + 3 alternatives
    originality breakdown + match URLs
    meaning cosine, entity retention, burstiness

Two numbers on every job, always: AI human % and Originality %. Never one slider for both.

3. NLP models

A humanizer is a constrained paraphraser. It must keep meaning, facts, names, numbers, quotes and citations; raise burstiness and perplexity; kill template diction; stay grammatical and on-register. It must not invent sources, change numbers, or follow instructions hidden in the document.

HIP — custom Pro recipe (2026 paper)

  • Collect human passages h. Have an LLM rewrite them into AI-ish a.
  • Fine-tune a base model (not a chat model) on a → h. Base models look more human to GPTZero / Pangram than instruction-tuned ones.
  • At inference apply 2–4 passes. Stop if detector is good AND meaning cosine ≥ 0.78.
  • Never 10 passes in production. The paper shows meaning dies.

Adversarial paraphrasing (2025): use an off-the-shelf LLM, but only resend sentences the detector still flags. Training-free. This is the production loop above.

3.4 Mini algorithm

Work per paragraph. At intensity 1–4, only touch sentences with V1 AI-prob ≥ 0.28.

IntensityNameTransforms
1–2LightReplace AI transitions. Delete empty hedges (It is important to note that).
3–4Light+POS-aware synonym swap. Contractions (off in academic).
5–6MediumSplit one long sentence or merge two short ones (burstiness). Rewrite formula openers.
7–8HeavyOne passive → active per paragraph. Safe clause reorder.
9–10AggressiveStronger synonym pressure. Higher meaning risk.

Keep 3 alternatives per touched sentence. Winner = 0.6 × humanScore + 0.4 × cosine_to_source. Burstiness B = std(sentence_length) / mean. Target 0.35–0.70. Below 0.35 force a split or merge. Above 0.90 undo.

3.5 Pro algorithm

Pro is a line editor, not a chatbot. System contract:

  • Keep every fact, number, name, quote, citation. Do not add examples, conclusions, or sources.
  • Vary sentence length. Prefer concrete verbs. Banned list = AI lexicon (section 4.5).
  • Leave sentinel tokens ⟦U0⟧ untouched. Register and intensity are parameters.
  • Return only the rewritten passage. Temperature 0.7–0.95, presence_penalty 0.4, max tokens ≈ 1.3× input.
  • Then run the SAME post-filters as Mini. The LLM is not trusted.
target_ai = 0.45 on Free,  0.28 on paid
max_pass  = 3     # never 10
for pass in 1..max_pass:
    rewrite only sentences with aiProb > 0.5
    stop if detect(draft).ai < target  AND  cosine(source, draft) >= 0.78

4. Filters

Filters are the difference between a demo and a product. Without them T5 and Claude both invent numbers, drop citations, and emit Furthermore. Run in this order. Fail closed.

4.1 Pre-filters — before any model sees the text

IDFilterAction
P0EncodingUTF-8, Unicode NFC, strip BOM
P1Invisible abuseRemove zero-width / bidi chars. Map Cyrillic lookalikes (а→a, е→e, о→o). Homoglyph attacks fool detectors AND plag checkers.
P2SizeEnforce plan word cap. Reject empty. Word count < 80 → scan unreliable
P3Languagefranc. English only in Phase 1. Refuse others instead of faking a score
P4ModerationBlock malware / CSAM / scam kits. Do not humanize those
P5PIIEmails, phones, IBANs — lock or refuse
P6Span protectionQuotes, citations, numbers, URLs, glossary → sentinels ⟦U0⟧
P7StructureHeadings, list markers, table cells stay units
P8Instruction fenceDocument is DATA. Ignore “ignore previous instructions” inside it

5. AI detection functionality

Detectors do not look for bad English. They look for statistical fingerprints of LLMs: low perplexity (next word too easy), low burstiness (sentence lengths almost equal), template diction, hedge stacks, near-zero contractions, parallel triads, uniform fluency.

We ship our own detector so we can iterate the humanizer against a stable target, avoid leaking Free-plan text to vendors, and show sentence-level reasons. Vendor APIs are a paid second opinion only.

Sentence AI-prob = sigmoid of a weighted sum of z-scored features, using a ±2 sentence window for local burstiness. Document score weights middle sentences 1.0 and first/last 0.75. % Human = 100 × (1 − document AI-prob).

5.3 V2 and the humanizer loop

V2 ensemble is in section 3.2. Expose V1 and V2 as a toggle. Tune the humanizer against OUR V2, then spot-check GPTZero weekly. Daily overfitting to one vendor dies on their next release.

Required loop: scan source → humanize → scan output → if document AI-prob did not fall by ≥ 0.08, or any sentence is still > 0.62, resend only those sentences → stop at 3 passes or when meaning cosine fails.

6. Plagiarism / originality functionality

Users say “plag free.” StealthWriter’s FAQ only really covers check A. We implement four checks.

CheckQuestionWhen
A Rewrite distanceDid we change the wording vs. this input?Day 1
B Internal corpusDoes this match another job, user, or seed library?Day 1 hashes; vectors Phase 2
C WebDoes this match the public internet?Phase 2–3, paid
D Citation honestyAre quotes and citations still on the same claims?Day 1

We will not build a Turnitin-scale web index. Use a search API or buy Copyleaks / Originality.ai. We will not get a Turnitin reseller API.

6.1 Check A — rewrite distance

Word 3-gram Jaccard vs input. Character 5-gram Dice as backup. Embedding cosine in Phase 2.

IntensityMax 3-gram Jaccard vs inputMin embedding cosine vs input
Light 1–3≤ 0.55≥ 0.88
Medium 4–7≤ 0.40≥ 0.82
Aggressive 8–10≤ 0.28≥ 0.78

Jaccard still high → flag “too close to input.” Cosine too low → we over-rewrote; roll that sentence back. Mid-filter M7 exists so Check A can pass.

6.2 Check B — internal corpus

Same family as Moss and Turnitin’s first stage. Normalize → character 9-grams → rolling hash → Winnowing (window = 4). Store (hash, user_id, job_id, offset) only — no raw text. Shared-hash rate > 0.18 → fine pass with word 5-gram alignment → match spans.

Phase 2: chunk 80–120 tokens, embed with e5, pgvector cosine ≥ 0.92 = near-paraphrase of stored content.

6.3 Check C — web originality (paid)

  • From each sentence, take the rarest 8-gram that is not a protected span.
  • Search that exact phrase on Serper / Bing / Brave. About 3 queries per 500 words.
  • If a top hit shares ≥ 60% tokens, fetch the page and align n-grams.
  • Attach {url, title, overlap, excerpt} to the sentence.
  • Allowlist boilerplate: proverbs, “p < 0.05 was considered…”, legal headers, standard IRB lines.

6.4 Check D — quotes and citations

If Pro rewrites a quotation, that is a new plagiarism bug (misquotation), not a feature. Quotes are locked (M4). Every quote in the output must exist in the input. Every (Author, Year) / [n] must remain within ±1 sentence of the same claim. If Pro dropped it, stitch it back.

6.5 Score we show

Originality        94%
  ├ rewrite vs input      91%     Check A
  ├ internal corpus      100%     Check B

Colors: ≥ 90 green · 75–89 amber · < 75 rose. Free plan: 0.45 A + 0.40 B. Paid: include C.

6.6 What we will not claim

  • We cannot detect idea plagiarism.
  • We cannot detect translated plagiarism until multilingual embeddings (Phase 3).
  • We cannot guarantee 0% Turnitin.
  • Humanizing a scraped article does not create a copyright license. Originality ≠ permission.
